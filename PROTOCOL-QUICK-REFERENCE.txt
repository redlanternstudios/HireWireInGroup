SECTION 8: ATOMIC I/O CONTRACT TABLE (❌ MISSING) — 8-10 HOURS **P0**
════════════════════════════════════════════════════════════════════════════

This is THE HEART of The Protocol. Every interaction documented.

What's needed: 175 contracts (35 pages × 5 interactions avg)

Each contract documents:
  • User input: "What the user does" (click, type, submit, etc)
  • API called: "Which endpoint" (POST /api/jobs/analyze, etc)
  • Request schema: "What data sent" (URL, file, form data)
  • Response schema: "What returned" (job_id, status, errors)
  • DB changes: "What's written" (INSERT, UPDATE operations)
  • Feedback: "What user sees" (toast, redirect, banner)
  • Error cases: "What can go wrong" (invalid URL, timeout, etc)
  • Recovery: "How to fix" (retry, manual entry, etc)

  ☐ Document ALL 175 interactions (or prioritize critical 30)
  ☐ Create lib/contracts/contract-validator.ts (runtime check)
